# H8a — lineage and `io.reuse_from` — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to
> implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a run can consume an earlier run's artifacts, and the record says which run and which
artifacts. `io.reuse_from(locator, step, name)` resolves a locator to a run directory by the two
rules § Lineage between runs states, reads the named artifact through the reader dispatch `io.write`
inverts, and every read that **returns** accumulates into `provenance.upstream` — the upstream's
`run_id`, its `code_hash`, its `parameters_hash`, and exactly which names were read. It mints the
`E-UPSTREAM-*` family and it builds the `run.yaml` **reader** that nothing in `src/` has.

**The payoff, stated so it cannot be rounded, and it is a table rather than a number.** The
2026-08-20 corrections in [the feasibility analysis](../../feasibility-llm-growth-studies.md)
§ Executability on this build retired *both* "six with no remaining core-side blocker" *and* the
"three" left standing after it, and ruled: **do not quote a single number — quote the table, or name
the dependency.** H8a moves exactly one row of that table.

| Figure | Before H8a | After H8a | Visible to `validate`? |
|---|---|---|---|
| Transplantable configs validating with zero errors | 8 of 8 | **8 of 8, unchanged** | yes — the only figure `validate` can see |
| Blocked on `io.reuse_from` | 6 — E3, E4, E6, C1, C2, C3 | **0** | no — a step-level call |
| Meet the `report_by`-under-`resample` gap | 7 — E1, E2, E4, E6, C1, C2, C3 | **7, unchanged** | no — a construction chosen inside `summarize_step`, and **H4's** |
| Free of every core-side dependency this analysis can name | 1 — E5 | **1, unchanged** | no — and only with the plugin written and installed |

**The row's label is repaired, not only its figure.** The correction's own table names that row
*"Need `io.reuse_from` (unbuilt)"*, and after H8a the parenthetical is false in the same breath as the
figure it labels — while six configs still *need* `io.reuse_from`, they are simply no longer blocked on
it. **Blocked-on** is the honest label, and task 10's report must say it changed a label and not a
count, so a reviewer comparing the two tables does not find a row differing in two ways with no way to
tell which was authorized.

**The fourth row does not move, and no task may write a sentence that moves it.** The
`report_by`-under-`resample` gap stays a named live dependency on seven of the eight, so "free of
every named dependency" stays where the correction put it. The design's § The payoff proposes a
third figure — *"8 of 8 transplantable, projected, under the standard the record applies"* — which is
a fifth number in all but name, produced by the standard that correction ruled inconsistent; see
[§ Corrections against the code](#corrections-against-the-code), correction 1. **What H8a may claim
is the second row plus three probeable facts**: both locator forms resolve, the read goes through the
registered reader, and `provenance.upstream` carries the upstream's own two hashes. It may not claim
that any config *executes* — the plugin must still be written and installed.

**Architecture.** One new module, one new method on the step-facing surface, one private keyword-only
parameter on `StepIO`, one defaulted keyword on `execute_plan`, one new `provenance` key, one shared
containment helper wired into three readers.

- **`lineage.py`** (new) holds `read_run_record`, `resolve_run`, `UpstreamResolver` and
  `UpstreamLedger`. It may import `run_record` and **`artifacts.py` may not import it**: measured,
  `run_record → runner → artifacts`, so `artifacts → lineage → run_record` closes a cycle. The
  annotation goes under `if TYPE_CHECKING:` in `artifacts.py` (which already imports `TYPE_CHECKING`
  for `UnitList`) and in `runner.py`. A reader who later replaces either with a plain import undoes
  Decision 2 rather than tidying an import.
- **`StepIO.__init__`** gains `upstream=None`, stored as `self._upstream`. **No public attribute, no
  `output_dir` on `io`** — the step-facing surface gains exactly the one method § Steps and
  artifacts' `io` table already documents and no new readable field.
- **`StepIO._contained`** is the shared helper, shaped like the `_resolve` that already ships, taking
  the base directory as an argument because `read_upstream`, `read_condition` and `reuse_from` each
  resolve against a different base. It refuses `..` traversal, an absolute path, and a symlink
  leading outside — **and nothing about the shape of the path: forward separators stay legal.**
- **`execute_plan`** gains `upstream: "UpstreamResolver | None" = None`, on `observer=`/`stop=`'s
  shipped precedent, and threads it into the `StepIO` it constructs per execution.
- **`cli.command_run`** constructs the resolver from `doc["data"]["output_dir"]` and the `repo_root`
  it already computed by walking up from the config path, and inserts `upstream` into the plain
  `dict` it hands `assemble_run_yaml`. **`run_record.py` is untouched** — it assembles only.

**Tech stack:** Python ≥ 3.11, `pytest`, `ruff`, `mypy`. No new dependency. The changes land in

## Global Constraints

Every task inherits all of these. They are copied verbatim rather than cross-referenced, because an
implementer sees only their own task brief.

**Commands.** Tests `uv run pytest`. Lint `uv run ruff check .`. Format `uv run ruff format .`.
Types `uv run mypy`. All four must pass before a commit. **Baseline at `28e311d`: 2456 passed, 1
skipped, 2 xfailed; 82 files formatted; 46 source files typed.**

**The gate literals move in this slice, and the tasks that move them are named.** `lineage.py` takes
`mypy` to **47 source files** from task 1 onward — an implementer who reads 46 as the expected number
after task 1 will reconcile a "failure" that is the new module. `ruff format --check` rises by each
new file: `src/publishable/lineage.py` and `tests/test_lineage.py` in task 1, and nothing else adds a
file. **Every task states its own DELTA on the test count, not an absolute**; compute the absolute
from your own previous run and reconcile any difference before committing.

**Run `uv run pytest` DIRECTLY, in the foreground, and wait for it.** It takes about two and a half
minutes at this baseline. **Never construct a wait, a monitor, a poll or a background run around it** —
several agents on preceding slices stalled that way and one stopped with a mutation still applied.
Clear `__pycache__` and any stale `pytest-of-*` temp directory before a run.

**Verify format with `uv run ruff format --check .`, never the bare form.** A previous brief in this
repo wrote the bare form where it meant `--check` and rewrote 67 files. **`ruff format` does not
process `.md`** — measured twice on preceding branches by copying a document, running the formatter
and diffing byte-identical; two agents nonetheless reverted documents on that misdiagnosis. A revert
is verified by **behaviour**, never by `git status`, and least of all by an account of what caused the
change.

**Every task says whether its surface is `validate`, `run`, a direct call, or documents.** Tasks 1,
2 and 4 are direct calls. Task 5 is a direct call plus `run`. Task 12 is a direct call. Tasks 3, 6,
7, 8 and 11 are `run`. Tasks 9 and 10 are documents. **No task's surface is `validate`, and none is
owed** — Decision 11: the locator is a *parameter*, and core cannot know which parameter is a run
locator without either a declared lineage block (refused by the same argument that removed the
condition selector) or reading the body of user Python (refused outright, § Greenfield only). **That
is a fact, not a filing**, and no task may file it as a gap.

**`validate` collects rather than aborting.** A refusal elsewhere never makes a later check
unreachable, and two independent readers on a preceding slice both recorded a mutation as blind on
that reasoning before a reviewer disproved it by building the fixture. It matters here only in the
negative: there is nothing in this family for `validate` to collect, so no task may infer anything
about a `validate` finding from H8a's behaviour.

**Nothing in H8a stops or alters a run, and each refusal task states what its tests assert
SURVIVES.** Measured at `28e311d`: `execute_plan`'s per-execution `try` is a bare `except Exception`
which records `status: "failed"`, writes an `executions.jsonl` line whose `error` is
`redact(f"{code} {type(exc).__name__}: {exc}")`, and **continues the loop**; `run.yaml` is then
written with the status `run_status` computes, and `latest` is pointed at the run. So every task
touching a refusal asserts, in this order: **`run.yaml` exists; a second `executions.jsonl` line
proves the next execution ran; the failed line's `error` carries the `E-UPSTREAM-*` code; and
`provenance.upstream` reflects Decision 6.** `CLAUDE.md`'s name for the failure this guards is *every
execution paid for, the record lost*.

**The exception class of each code is observable, so it is pinned rather than argued in prose.**
`type(exc).__name__` lands in the ledger line, so `"E-UPSTREAM-NAME ArtifactError"` is an assertion
rather than a comment. The assignment, with its grounds: `E-UPSTREAM-NAME` and
`E-UPSTREAM-ARTIFACT-MISSING` are **`ArtifactError`**, following the mechanism they share with
`E-ARTIFACT-NAME` and `E-ARTIFACT-UNREADABLE`, which the shipped `_resolve` and `_read` already
raise; every other `E-UPSTREAM-*` is a **`ContractError`**, because it is a fault in what the caller
asked for rather than in addressing an artifact. Both are caught by the same bare `except`, so this
changes no control flow and is a naming decision made observable on purpose.

**`provenance.upstream` is ALWAYS written, and `[]` when there is no upstream** (Decision 7), on
`input_manifest_changed: []`'s in-block precedent for a **list** rather than on `apparatus: null`'s
for a scalar-or-object. `[]` and absent are both falsy and one truthiness assertion cannot tell them
apart — which is the whole content of Decision 7 and why Fixture E has **two** assertions.

**One prescribed mutation is DROPPED, and saying so is the point.** Replacing `output_dir` with
`run_dir.parent` cannot be caught by any fixture: core allocates every run directory under the
config's own `output_dir`, so the two are equal in every reachable state and the two branches produce
identical results. **A mutation is a claim too.** The proxy is prevented **structurally** instead:
under Decision 2 the resolver is built in `command_run` from `doc["data"]["output_dir"]` and `run_dir`
is never in its scope. No task may add a test for it, and no task may describe it as tested.

**Every literal is computed, not guessed, and every mutation names the assertion that catches it AND
why the two branches can differ.** Across the two H7d parts at least seven prescribed mutations could
not discriminate — one was what the shipped code already did, one made both branches identical, one
was intercepted by an assert an earlier batch added, one was blind because the fixture's interval was
zero-width under every construction. **A mutation that changes nothing is evidence about the tests,
not about the code**, and "no mutation reaches this" and "no mutation *can* reach this" are different
claims.

**Read every fixture literal back from what produced it.** Measured at `28e311d`: `run_a_project`
generates a step named `step02_step09_publish` when the caller asks for `step09_publish` — the
scaffold prefixes. **A hard-coded step name is a guessed literal**; read it from `sweep.yaml` or from
the upstream record's own `execution` block. The same rule covers every hash: Fixture R's hashes are
read back from its own `run.yaml`, never written as literals, because a literal would pin the test to
this repo's tree at fixture-writing time.

**Resolve a downstream run directory through `latest`, never through `run_a_project`'s return, in any
test that pre-places an upstream under the downstream's `output_dir`.** Measured at `28e311d`:
the helper does `next(results_dir.glob("run_*"), None)` and `Path.glob` has **no defined order**; a
synthesized upstream directory must be named `run_…` for the relative form to address it at all, so
it matches that glob, and if it were selected the helper returns `run_dir: None` (it has no
`executions.jsonl`) and the test crashes on `doc["run_dir"]` rather than failing an assertion. In one
observed run the downstream was selected — which is the worse case, because it means the collision is
**latent** and would flip later. `point_latest` writes `<output_dir>/latest` as a symlink to the run
directory's **name**, falling back to `latest.txt` holding the same name; resolve either.

**Mutation discipline, every task.** Keep a copy of the file before mutating. Apply the named
mutation. Run the named test, confirm it **FAILS**, then run the **full, unfiltered** suite in the
foreground. Then `find . -name __pycache__ -type d -exec rm -rf {} +`. Then revert **by editing the
file back in place** — **never `git checkout -- <file>`**, which destroys uncommitted work and has
been mistaken for a revert three times in this repo. Verify the revert by **behaviour** and by
diffing against your saved copy, never by `git status`.

**A safety argument in a comment is a claim, and needs a mutation like any other.** H7d Part A's only
Critical came from an unreachability claim a three-line fixture falsified, and **five consecutive
batches on Part B shipped a false comment**, the last promising that a committed task would fix the
line it sat on. **No comment anywhere in this slice may say a `reuse_from` refusal "cannot reach the
plan".** Fixture F is that claim's mutation: patch `reuse_from` to raise on every call and check

**When a change makes a sentence false, that sentence is in the diff already being read.** Task 12
changes what `read_upstream` and `read_condition` do; every docstring and comment on both, and the
§ Errors row for the code they raise, is part of task 12's own diff. **Prefer deleting a claim to
rewriting it** — a rewrite invents, a deletion cannot — and when you edit a docstring, re-read the

**Answering a question with a proxy** is this repo's most expensive habit; both fail-opens in H7a and

### Fixture L — the two locator forms, and the mismatch

Synthesized run directories under one `output_dir`, plus one copied to `elsewhere/moved_run/` whose
record still holds its original `run_id`.

- **Relative form:** `reuse_from("run_…_aaa", …)` resolves under `output_dir` and reads.
- **Absolute form** on `elsewhere/moved_run/`: reads, and the recorded `run_id` is the **record's**.
  A second assertion checks the string `moved_run` appears **nowhere** in the rendered record — the
  pin for *"records the resolved `run_id` and never the path"*, asserted on the **raw text**, because
  a defect that lives in how a value is written can be normalised away by a reader.
- **`<output_dir>/latest`** — **the fixture creates the symlink itself.** `point_latest` falls back to
  `latest.txt` where symlinks are unavailable, in which case no `latest` path exists at all and the
  expected code would be `-RECORD-MISSING` rather than `-RUNID-MISMATCH`; relying on the fallback
  would make the arm platform-dependent. Via the **absolute** form: reads, and records the resolved
  id. Via the **relative** form: `E-UPSTREAM-RUNID-MISMATCH`, which is Decision 1's named asymmetry.

row overclaims. **Task 10 may not mint a fifth number.**

**2. Decision 1's `latest` asymmetry survives only if the relative form compares the locator AS
GIVEN, and the design does not say which comparison.** § The discriminating fixtures asserts
`E-UPSTREAM-RUNID-MISMATCH` for `<output_dir>/latest` through the relative form, and § What did not
survive describes the fault as *"a directory under `output_dir` whose basename and whose record's
`run_id` differ"*. **Measured:** `run_identity.point_latest` writes `latest` as a symlink whose
target is the run directory's **name**, so a comparison made against a *resolved basename* finds the
real `run_id` on both sides, agrees, and never raises — the relative form would quietly start
accepting `latest` and the documented asymmetry would die with every arm still green. Task 2 step 2
therefore prescribes the locator-as-given comparison, and names the mutation that catches the other
reading. **This is a sharpening, not a widening**: the renamed-directory arm the design already
prescribes is the same rule, and one rule covers both.

**3. `read_upstream` and `read_condition` enforce NO name rule, re-confirmed by live probe at
`28e311d`.** `H8-SCOPING.md` § 9's task 5 says `io.reuse_from` inherits *"the relative-path rules
`io.write`/`read_upstream` already enforce"*; the design already records that as false. Re-measured
independently here rather than carried: a `StepIO` over a throwaway tree returned the contents of
both `../../../secret/x.json` and an absolute path through `read_upstream`, while the ordinary
`ok.json` read succeeded — so the arms are distinguishable and the fixture is not vacuous. **There
was no rule to inherit**, and this is why the design's task 5 splits into tasks 5 and 12: one builds
new surface, the other changes shipped behaviour.

**4. A test that pre-places an upstream under the downstream's `output_dir` cannot use
`run_a_project`'s returned `run_dir`.** The design's Fixture L needs synthesized run directories
under one `output_dir` and Fixture R needs a real run; the relative locator form requires the upstream
to sit under the **downstream's** `output_dir`, so the two must share one. **Measured:** the helper
returns `next(results_dir.glob("run_*"), None)` and `Path.glob` has no defined order; a synthesized
upstream must be named `run_…` for the relative form to address it, so it matches that glob, and if
it were selected the helper returns `run_dir: None` — it has no `executions.jsonl` — and the test
crashes on `doc["run_dir"]` rather than failing an assertion. In one observed run the downstream was
selected, which is the **worse** outcome: the collision is latent and would flip later. Prescribed
instead: resolve the downstream through `<output_dir>/latest`, with the `latest.txt` fallback.
`run_a_project` itself is not modified — **this correction is about the fixtures, not the helper.**

**5. The exception class of each `E-UPSTREAM-*` code is a decision the design leaves open, and it is
observable, so the plan rules it and pins it rather than arguing it.** Decision 10 says each code is
*"a `ContractError` or `ArtifactError`"* without assigning them. Measured: `execute_plan`'s
per-execution handler writes `redact(f"{code} {type(exc).__name__}: {exc}")` into both records, so the
class **lands in `executions.jsonl`** and is assertable. Ruled in § Global Constraints:
`E-UPSTREAM-NAME` and `E-UPSTREAM-ARTIFACT-MISSING` are `ArtifactError`, following the mechanism they
share with the shipped `E-ARTIFACT-NAME` and `E-ARTIFACT-UNREADABLE`; every other `E-UPSTREAM-*` is a
`ContractError`. Both are caught by the same bare `except Exception`, so this changes no control flow.

**6. `ArtifactError`'s own gloss is false in both places it appears, and task 12 makes it more so.**
`errors.py`'s class docstring and § Errors core raises' exception tree both read *"core will not write
this"* — while the shipped `_read` already raises it on a **read** under `E-ARTIFACT-UNREADABLE`, and
tasks 5 and 12 add read-side raises. The design does not mention it. Added as task 9 step 4, in both
files, because a sweep that fixes the document and leaves `errors.py` is the shape `CLAUDE.md` names.
Also recorded: § Errors core raises' `E-ARTIFACT-NAME` row today groups a name escape with `io.append`
and an unwritable extension, so it reads as write-side — task 9 step 3's repair, and the row's unit of

**7. `lineage.py` moves two gate literals, and the design does not name them.** Measured at
